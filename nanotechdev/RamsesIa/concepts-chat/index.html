Chat et modèles open source

Statut : ✅ Confirmé dans le code ; les IDs exacts se règlent dans /operator​

Ramsess-AI n'appelle pas Azure OpenAI ni une API payante par token. Le texte sort d'Ollama sur ollama-gpu-vm. La console /operator > Modèles IA publie le catalogue vu sous le composeur.

Concepts du chat​

ConceptCe que ça veut dire ici
Chat directSeul mode Public. Pas de vase, pas de citations [Source N].
Streaming SSEPOST /chat/stream. La bulle se remplit au fil des fragments.
Prompt serveurLe client n'envoie pas de rôle system. ApiPublic préfixe le prompt NaNo-IA.
Verrou de langueChatResponseLanguagePolicy. Français par défaut. Autre langue seulement si le message est clairement rédigé ainsi. Message court / mal transcrit → français.
Raisonnement <think>DeepSeek R1 écrit souvent dans un bloc caché. L'UI affiche la réponse après </think>. S'il n'y a que du raisonnement, ce texte devient la bulle (évite « Réponse 0 jetons »).
Salutationbonjour, salut, hello, hi, hey exacts → réponse française figée, 0 GPU.
QuotaUn message utilisateur accepté par jour, pas des tokens. « Et ensuite ? » consomme 1.
Fair UsePlafonds techniques avant le quota : taille message, image, num_predict, fenêtre de contexte. Identiques entre forfaits au départ.
Follow-upsJusqu'à 3 questions dans un bloc [FOLLOW_UPS] (Public les lit encore dans le flux).
Budget jetonsCompteur visible (question / réponse). La réponse visible ignore le raisonnement masqué.
HistoriqueConversations sidebar surtout locales (prompts 19 / 19A / 19B). L'API reçoit un historique borné, sans system.

Un modèle multilingual (DeepSeek, Qwen) dérive si le verrou est trop faible. C'est le bug « réponse en swahili » : français mal transcrit + R1 + historique hello. Le verrou et le repli <think> sont dans le code ; Cloud Run ne les a qu'après déploiement de cette révision.

Modèles open source utilisés​

Les identifiants ci-dessous sont ceux déjà vus dans le dépôt et les journaux Public. Le propriétaire peut en publier d'autres s'ils sont déjà pullés sur la VM.

RôleFamilleExemple d'ID Ollama / moteurOù c'est tranché
Chat texteDeepSeek R1 (raisonnement)deepseek-r1:14bDéfaut deploy-public.yaml (Ollama__ChatModelId)
Chat texteQwen 2.5qwen2.5:14bMême VM ; souvent le défaut RAG. Utilisable Public s'il est au catalogue
VisionQwen3-VL Instructqwen3-vl:8b-instructJournal 2026-11-03 : photo livre validée. Référence Public
Vision (ancien)Qwen2.5-VLqwen2.5vl:7bValeur historique ApiPublic, à remplacer par Instruct en console
Embeddingsnomicnomic-embed-textRAG seulement. Public n'indexe pas
DictéeFaster-Whisper via SpeachesSystran/faster-whisper-small / whisper-large-v3-turboSPEECH_ENDPOINT, jamais OLLAMA_VM_IP

Règles d'exploitation :

  • Aucun pull automatique depuis Cloud Run ou Hugging Face au runtime.
  • Chat texte et Vision sont deux modèles. Une image bascule sur vision_model_id si le modèle choisi ne lit pas les images.
  • Instruct (VL) plutôt qu'un modèle « thinking » pour la caméra : moins de <think>, réponse visible.
  • DeepSeek R1 : latence 30–60 s fréquente. D'où le raccourci salutation et le Fair Use num_predict.

Même bibliothèque d'inférence que l'Entreprise. Contrats et plugins métier RAG absents côté Public.

Ce que le composeur envoie au modèle​

EntréeTraitement
TexteValidé (taille Fair Use) puis historique + prompt serveur
Image (fichier / caméra)MIME + taille ; modèle vision ; pas d'URL d'image inventée rendue en <img>
AudioMediaRecorder → POST /speech/transcribe → texte dans le composeur, pas d'envoi auto
DOCX / PPTX / TXT / MDExtraction serveur, texte marqué « donnée non fiable », compte dans le budget
PDF / ExcelRefusés en Public (prompt 21)

Les images Markdown émises par le modèle sont remplacées par un badge « Image non affichée » (exfiltration + URL fictives).
